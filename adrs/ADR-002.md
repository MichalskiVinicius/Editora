# ADR-002: Estratégia de Desacoplamento de Código com DIP e Padrões GoF

- **Status:** Aprovado
- **Data:** 2026-10-05

## Contexto
A plataforma integra sistemas externos (gráficas legadas via XML/EDI, serviços de IA). Mudanças nesses sistemas não devem quebrar o domínio.

## Decisão
Aplicar o **Princípio de Inversão de Dependência (DIP)**: o domínio depende de abstrações e a infraestrutura as implementa. Usar **Factory Method** para criar conectores e **Adapter** para traduzir payloads legados (XML/EDI) para o formato do domínio (JSON).

## Consequências e Trade-offs
- (+) Trocar um conector não afeta as regras de negócio.
- (+) Facilita testes com implementações falsas.
- (-) Mais classes/arquivos e uma curva de aprendizado maior.
- (-) Risco de sobre-engenharia se aplicado onde não há variação real.

## Alternativas consideradas
Chamar as integrações direto da lógica de negócio: descartado pelo acoplamento.
